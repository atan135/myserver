# 简化版打包、交付与部署流程

适用于已完成服务器初始化的常规发布。业务代码和 CSV/场景配置修改必须先提交并推送到 Git；WSL 工作区必须位于 Linux 原生文件系统（例如 `~/src/MyServer`），且 Docker Registry 登录状态有效。

下文中的 `<release-id>` 必须使用第一步输出的实际值，并在后续两步保持完全一致。

## 1. WSL 构建并推送镜像

```bash
cd ~/src/MyServer
git pull --ff-only origin main
bash scripts/docker/publish-release.sh
```

该步骤会拉取最新代码、构建并推送镜像，提交镜像 digest 锁定文件。首次构建或依赖缓存失效时耗时会较长。

成功后记录末尾输出的 release ID：

```text
release_id=v0.1.0-<short-commit>
```

## 2. WSL 上传 Release Bundle

WSL 中需要准备权限为 `600` 的 Linux 原生 SSH 私钥，例如 `~/.ssh/id_<remote-user>`。

```bash
cd ~/src/MyServer

bash scripts/docker/upload-release-bundle.sh \
  --release-id 'v0.1.0-<short-commit>' \
  --host '<remote-ip-or-hostname>' \
  --port '<remote-ssh-port>' \
  --user '<remote-user>' \
  --identity ~/.ssh/id_<remote-user> \
  --caddy-auth-host 'api.game.example.com' \
  --caddy-admin-host 'admin.game.example.com' \
  --caddy-email '<ops-email>' \
  --game-proxy-host 'game.example.com'
```

成功标志：输出 `uploaded_release=/data/myserver/release/<release-id>`。

## 3. 服务器应用 Release

以部署用户登录服务器后执行：

```bash
/data/myserver/apply-release.sh \
  --release-id 'v0.1.0-<short-commit>' \
  --actor '<remote-user>@'"$(hostname -s)"
```

成功标志：输出 `current_release=/data/myserver/release/<release-id>`，并列出运行中的 Compose 服务。

部署脚本会自行按 digest 拉取镜像、执行 migration gate、等待 required readiness，再启动 Caddy；不要额外执行 `docker compose down` 或手工修改服务器 secret。
