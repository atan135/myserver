# 服务器初始化实操

## 1. 定位

本文记录 MyServer 单机 Docker 宿主机的已验证初始化流程。它是[服务器 Docker 初始化与更新](./服务器Docker初始化与更新.md)的执行补充，不替代首次发布、数据库迁移、服务发现校验、接流量或回滚流程。

本文不记录主机名、公网 IP、SSH 私钥、镜像仓库凭据、镜像加速器账号标识或生产 secret。此类信息只能留在受控密码管理系统或服务器本地 `secrets/` 目录。

## 2. 当前初始化结果

已验证的宿主机基线：

| 项目 | 当前状态 |
|---|---|
| 操作系统 | Ubuntu 24.04 LTS，`x86_64` |
| 计算资源 | 4 vCPU，约 7.7 GiB 内存，约 3.8 GiB swap |
| 内核能力 | cgroup v2、NTP 时间同步正常 |
| 根分区 | 约 39 GB，仅用于系统，不承载 Docker 数据 |
| 数据盘 | ext4 挂载于 `/data`，当前可用约 56 GB |
| Docker 数据目录 | `/data/myserver/docker` |
| Docker 日志 | `local` driver，单容器最多 `20m x 3` |
| Redis 内核参数 | `vm.overcommit_memory=1` |
| Redis 持久化 | 发布清单使用 AOF `everysec`，显式禁用 RDB snapshot（`save ""`） |
| Docker Hub 代理 | `https://docker.m.daocloud.io`，已通过 `hello-world` 验证 |

当前 `60 GB` 数据盘满足单机正式发布的至少 `50 GB` 基线。该容量仍较紧凑，必须持续监控 PostgreSQL、Redis AOF、日志和镜像占用；可恢复备份应使用独立磁盘、对象存储或异机存储，不与 Docker data-root 争抢空间。

当前仅完成 Docker 宿主机初始化，尚未部署 MyServer Compose 清单、业务镜像、数据库 migration、TLS 反向代理或玩家入口。

## 3. 初始化前检查

先确认数据盘已经挂载且不是待格式化的空白设备。当前实例直接复用已有 `/data`，不得执行 `mkfs`、修改其 UUID 或覆盖已有 `/etc/fstab` 条目。

```bash
findmnt /data
lsblk -f
df -hT / /data
stat -fc %T /sys/fs/cgroup
timedatectl status
```

若 `/data` 未挂载、文件系统类型不是预期的 ext4/xfs，或目录已有不明业务数据，应停止并先完成磁盘归属确认。

## 4. 安装 Docker Engine

使用 Docker 官方 Ubuntu 软件源，不使用 Snap 版 Docker，也不在生产服务器安装 Node.js、Rust 或项目构建工具。

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin
```

安装后先停止 Docker，再写入数据目录和 daemon 配置，避免后续镜像与 volume 默认堆积到根分区：

```bash
sudo systemctl stop docker.service docker.socket
```

## 5. 数据目录与权限

```bash
sudo install -d -m 0755 \
  /data/myserver/docker \
  /data/myserver/release \
  /data/myserver/data/postgres \
  /data/myserver/data/redis \
  /data/myserver/data/nats \
  /data/myserver/backups \
  /data/myserver/logs \
  /data/myserver/sockets

sudo install -d -m 0700 /data/myserver/secrets
```

由 `gameops` 接收 release、生成本机 secret 并执行 Docker Compose 时，额外设置最小可用权限：

```bash
sudo chown root:gameops /data/myserver/release
sudo chmod 2770 /data/myserver/release
sudo chown gameops:gameops /data/myserver/secrets
sudo chmod 0700 /data/myserver/secrets
sudo usermod -aG docker gameops
```

`release/` 的 setgid 位保证每个 release 子目录继承 `gameops` 组；它不存放 secret。`secrets/` 只允许该受控运维账号读取，所有其中的 env 文件必须为 `0600`。加入 `docker` 组等价于较高宿主机权限，只应授予该受控账号。

不要在此阶段递归 `chown` PostgreSQL、Redis、NATS 数据目录。实际 Compose 镜像确定后，先确认其运行 UID/GID，再只对对应数据目录授予最小权限。

## 6. Docker daemon 配置

首次写入前必须确认 `/etc/docker/daemon.json` 不存在。若它已经存在，应合并合法 JSON 字段，不能用下列示例覆盖其中已有的代理、证书或其他受控设置。

```bash
sudo test ! -e /etc/docker/daemon.json \
  && echo "daemon.json 不存在，可创建"
```

当前单机配置如下：

```json
{
  "data-root": "/data/myserver/docker",
  "log-driver": "local",
  "log-opts": {
    "max-size": "20m",
    "max-file": "3"
  },
  "registry-mirrors": [
    "https://docker.m.daocloud.io"
  ]
}
```

其中：

- `data-root` 必须保留，不能回退到 `/var/lib/docker`。
- 使用 `local` 日志驱动，避免 `json-file` 以数百 MB 的单容器日志上限快速占满 60 GB 数据盘。
- 镜像代理仅用于 Docker Hub 公共基础镜像拉取；它不是生产业务镜像仓库，也不应加入多个未经验证的公共地址。
- 不设置 `experimental`、`insecure-registries` 或无用途的 Builder 缓存配额。生产服务器不执行 `docker build`。

建议先写入临时文件并校验：

```bash
sudo tee /tmp/myserver-daemon.json > /dev/null <<'EOF'
{
  "data-root": "/data/myserver/docker",
  "log-driver": "local",
  "log-opts": {
    "max-size": "20m",
    "max-file": "3"
  },
  "registry-mirrors": [
    "https://docker.m.daocloud.io"
  ]
}
EOF

sudo dockerd --validate --config-file /tmp/myserver-daemon.json
sudo install -m 0644 /tmp/myserver-daemon.json /etc/docker/daemon.json
sudo rm /tmp/myserver-daemon.json
```

为确保 `/data` 挂载完成后才启动 Docker，添加 systemd drop-in：

```bash
sudo install -d -m 0755 /etc/systemd/system/docker.service.d

sudo tee /etc/systemd/system/docker.service.d/10-data-mount.conf > /dev/null <<'EOF'
[Unit]
RequiresMountsFor=/data/myserver/docker
EOF
```

## 7. Redis 内核参数与启动

```bash
echo 'vm.overcommit_memory=1' \
  | sudo tee /etc/sysctl.d/99-myserver-redis.conf > /dev/null
sudo sysctl -p /etc/sysctl.d/99-myserver-redis.conf

sudo systemctl daemon-reload
sudo systemctl enable --now docker
```

## 8. 镜像代理验证

先验证代理本身可达：

```bash
curl -4 -sS -o /dev/null -w 'HTTP=%{http_code}\n' \
  --connect-timeout 10 \
  --max-time 20 \
  https://docker.m.daocloud.io/v2/
```

`200`、`401` 或 `404` 表示 Registry HTTP 端点可达。随后分别验证显式代理地址和普通 Docker Hub 镜像名：

```bash
sudo docker pull docker.m.daocloud.io/library/hello-world:latest
sudo docker pull hello-world:latest
sudo docker run --rm hello-world:latest
```

`Hello from Docker!` 表示 Docker client、daemon、镜像代理、镜像存储和容器运行链路均正常。

## 9. 完成后核验

```bash
sudo docker version
sudo docker compose version
sudo docker buildx version
sudo docker info --format \
  'cpus={{.NCPU}} memory={{.MemTotal}} root={{.DockerRootDir}} logging={{.LoggingDriver}} cgroup={{.CgroupVersion}}'

sysctl vm.overcommit_memory
df -hT /data /data/myserver/docker
systemctl is-active docker
sudo ufw status verbose
```

Docker `root` 必须为 `/data/myserver/docker`，日志驱动必须为 `local`，cgroup 版本必须为 `2`，Docker 服务状态必须为 `active`。

## 10. 网络与上线前边界

- 防火墙和云安全组应继续默认拒绝入站。当前初始化阶段只保留受控 SSH 管理入口。
- 不开放 `3000`、`3001`、`7000`、`7500`、`7101`、`9001` 至 `9004`、`4222`、`8222`、`5432`、`6379` 等内部端口。
- 只有 Compose、TLS 反向代理、入口认证和服务发现就绪后，才按[服务器 Docker 初始化与更新](./服务器Docker初始化与更新.md)开放 `80/TCP`、`443/TCP`、`4000/UDP` 及实际需要的 TCP fallback。
- 管理后台必须走 VPN、零信任入口或 IP allowlist，不能直接暴露为无保护公网服务。

## 11. 后续必须完成的事项

1. 保持 `/data` 至少 50 GB，并为备份使用独立磁盘、对象存储或异机存储。
2. 建立受控私有镜像仓库。业务镜像和基础镜像应以不可变 digest 发布，生产服务器不执行 `docker build`、`npm install`、`cargo build` 或 `git pull`。
3. 实现并审阅 `deploy/docker/` Compose、Dockerfile、配置和 `images.lock.json`，详见[本地 Docker 镜像打包与发布](./本地Docker镜像打包与发布.md)。
4. 按[服务器 Docker 初始化与更新](./服务器Docker初始化与更新.md)完成数据库备份、migration runner、registry/readiness、drain、回滚和监控能力后，再接入外部流量。

## 12. Docker 配置回退

修改 `daemon.json` 前应先备份。镜像代理或新配置导致 Docker 无法正常启动时，使用备份回退：

```bash
sudo cp -a /etc/docker/daemon.json.bak.<timestamp> /etc/docker/daemon.json
sudo systemctl restart docker
sudo systemctl is-active docker
```

不得通过删除 `/data/myserver/docker`、执行 `docker system prune -a` 或重装 Docker 来处理配置问题；这些操作可能删除本地镜像、容器或 volume 数据。
