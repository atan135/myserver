# 可观测性容量与故障恢复 Checklist

## 目标

统一 MyServer 多服务的日志、指标、健康状态、容量阈值、告警和故障演练，在现有 metrics collector、Redis 快照、NATS 通道和服务发现检查基础上形成可操作的生产治理闭环。

## 基础原则

- [ ] 指标必须能回答是否可用、为何退化、影响范围和是否恢复。
- [ ] health、readiness 和 liveness 语义分离。
- [ ] 标签限制基数，禁止直接使用 player_id、character_id 或 room_id 作为常驻指标标签。
- [ ] 故障演练默认可控、可停止，不自动对真实环境执行。
