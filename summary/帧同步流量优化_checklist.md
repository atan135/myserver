# 帧同步流量优化 Checklist

## 目标

围绕当前 `game-server -> game-proxy -> client` 的帧同步链路，建立可量化的流量基线，并逐步降低单玩家平均下行带宽。优化重点是减少无效帧数据、压缩高频输入 payload、治理快照和校正频率、补齐出口流量指标与压测方法。该 checklist 只规划后续开发任务，不要求当前立即改代码。

当前已知背景：

- 玩家协议使用自定义 14 bytes 包头 + Protobuf body。
- 房间主链路是 `PlayerInputReq` 上行、`FrameBundlePush` 下行。
- `FrameBundlePush` 当前按房间每帧广播输入集合，输入集合可能包含框架补出的空输入。
- `movement_demo`、`combat_demo` 等玩法还会额外产生移动校正、战斗事件和快照推送。
- 带宽目标不能只按在线人数估算，应按同房人数、活跃率、帧率、单输入大小、快照频率和 KCP/重传冗余综合评估。

## 基础原则

- [ ] 不改变“服务端权威推进、客户端按帧回放”的核心语义。
- [ ] 关键流量优化应有配置或安全闸，便于联调定位问题。
- [ ] 不以牺牲断线重连、观战恢复、房间迁移和回放能力为代价压缩数据。
- [ ] 先建立真实指标，再改协议和广播策略，避免凭估算盲目优化。
- [ ] 区分模拟帧率和网络下发频率，避免把 20fps tick 固化为 20fps 全量网络广播。
- [ ] 服务端协议变更必须同步更新客户端、mock-client 和协议文档，以当前开发版本为唯一目标。
- [ ] 每个阶段完成后补充对应测试、压测或手动验收记录。

- 结束时间：

- [ ] 已能通过指标直接看到 `game-proxy` 对客户端总出口 Mbps 和单连接平均 KB/s。
