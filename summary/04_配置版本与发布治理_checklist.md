# 配置版本与发布治理 Checklist

## 目标

在 game-server CSV 加载与热更基础上，建立“服务代码仓库 + 配置仓库”双 Git 仓库的版本、发布、兼容和回滚治理。服务版本以服务仓库 Git tag/commit 和 Docker image digest 为准，配置版本以配置仓库 Git tag/commit 和配置包 hash 为准；两者可以独立发布，但通过不可变部署 manifest 固定实际运行组合。首期覆盖现有 CSV 与场景配置，不建设在线数值编辑器或独立配置中心。

## 当前核对说明（2026-08-26）

- 本清单目标仍然有效，继续作为配置版本与发布治理的主清单；本次直接在原清单上更新状态，不另建 v2。
- 目标模型已收敛为双仓库：服务仓库负责代码、Docker 镜像和服务 release；配置仓库负责 CSV、scene/grid 及其他非敏感配置 release。
- “独立发布”只表示两个仓库可以分别构建和发布，不表示任意服务版本与任意配置版本都兼容；实际部署必须使用经过校验的 `app_release + config_release` 组合。
- 当前代码已经落地 CSV 的 schema signature、部分业务/跨表校验、候选运行时配置构建、派生 catalog 重建、成功后原子替换和失败保留旧版本。
- `RuntimeGameConfig.version` 目前只是进程内递增版本号，不是跨实例、跨环境可验证的配置仓库版本；双仓库配置包、部署 manifest、兼容范围、配置独立发布和组合回滚仍未完成。
- 现有 game-server Room rollout、`room_version`、transfer schema/checksum 和 release bundle `SHA256SUMS` 分别属于 Room 迁移或整包发布能力，不能替代配置版本治理。
- 代码优先于旧文档：当前 `ConfigTables` 已包含 `SceneInteraction`、`SceneNpc`、`SceneContext`、`TitleTable`、`DisciplineTable`、`CharacterProgressTable` 等表；CSV 热更现状文档中的表格需要后续同步。
